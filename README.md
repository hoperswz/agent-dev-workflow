# Agent Dev Workflow

[English](./README.en.md)

一套我在使用 Coding Agent 开发过程中逐步整理出来的开发工作流。

它的目标不是让 AI 一次把代码写对，而是让 Agent 在面对稍复杂的开发任务时，能够按照一个**可检查、可中断、可恢复**的过程完成工作。

目前主要在 Codex 中使用。

---

## 为什么做这个

一开始使用 Coding Agent 时，我的方式很简单：

> 告诉它要做什么，然后让它直接修改代码。

对于简单任务，这种方式通常没有问题。

但任务复杂以后，我逐渐遇到了一些情况：

* 需求还没有完全理解，Agent 已经开始写代码；
* 会话越来越长，前面确认过的内容开始丢失；
* 任务做到一半中断，下次需要重新交代上下文；
* Agent 说“已经完成”，但实际上并没有完成充分验证；
* 一个复杂任务包含很多步骤，很难知道当前到底做到哪里。

所以我开始尝试给 Agent 增加一套开发规则。

核心思路很简单：

```text
理解需求
   ↓
澄清问题
   ↓
拆解任务
   ↓
创建任务文档
   ↓
执行任务
   ↓
验证结果
   ↓
记录进度
```

Agent 不再依赖聊天上下文记住任务进度，而是把任务状态持续记录在项目中。

即使会话中断，下一次也可以通过任务文档、Git 状态和当前代码重新确认现场，然后继续之前的任务。

---

## 核心原则

这套工作流目前主要遵循几个原则：

### 1. 不确定时，不直接写代码

面对稍复杂的任务，Agent 首先需要理解需求。

存在不确定内容时，先提出问题。

只有需求明确以后，才进入任务拆解和开发。

### 2. 复杂任务必须落盘

任务确认以后，会在项目中创建任务文档：

```text
tasks/
└── YYYY-MM-DD/
    └── YYYY-MM-DD-HH-mm-ss-任务名.md
```

任务文档会记录：

* 任务目标；
* 已确认需求；
* 不包含范围；
* 任务拆解；
* 任务依赖；
* 当前状态；
* 验收标准；
* 验证结果；
* 当前实际进度；
* 中断恢复信息。

### 3. 任务状态必须和实际情况一致

Agent 不能因为“代码已经写完”就认为任务已经完成。

任务是否完成，需要结合：

* 代码；
* 测试；
* 验证结果；
* Git 工作区状态；
* 必要的人工验收。

### 4. 完成必须有验证

Agent 在宣告任务完成前，需要执行与任务风险相匹配的验证。

不能仅凭：

> “看起来应该没问题。”

就认为任务已经完成。

### 5. 中断以后可以恢复

任务暂停或会话中断前，需要留下恢复信息。

重新开始时，Agent 不会单纯相信之前的聊天记录，而是重新检查：

```text
任务文档
   +
Git 状态
   +
当前代码
   +
验证记录
```

确认实际状态以后，再继续开发。

## 快速开始

将 `AGENTS.md` 放到你的项目根目录即可。

### 方式一：一键安装

在需要使用这套工作流的 **Git 项目根目录**执行。以下命令固定安装 `v1.0.0`，不会跟随仓库后续提交发生变化。

#### Linux / macOS

```bash
curl -fsSL https://raw.githubusercontent.com/hoperswz/agent-dev-workflow/v1.0.0/scripts/install.sh | bash
```

#### Windows PowerShell

```powershell
$installer = irm https://raw.githubusercontent.com/hoperswz/agent-dev-workflow/v1.0.0/scripts/install.ps1
& ([scriptblock]::Create($installer))
```

安装完成后：

```text
your-project/
├── AGENTS.md
├── src/
├── ...
└── .git/
```

安装脚本支持普通 Git 仓库和 Git worktree，不会覆盖已经存在的 `AGENTS.md`。如果下载失败，临时文件会被清理，不会留下残缺的目标文件。

### 方式二：手动安装

下载仓库中的：

```text
AGENTS.md
```

复制到自己的项目根目录即可。

## 怎么使用

安装完成后，不需要专门输入某个固定 Prompt。

正常向 Coding Agent 提出开发需求即可。

例如：

```text
帮我给用户模块增加登录日志分页查询功能。
```

对于简单修改，Agent 可以直接处理。

对于复杂任务，Agent 会按照 `AGENTS.md` 中定义的流程：

```text
理解需求
   ↓
发现疑问
   ↓
与你确认
   ↓
拆解任务
   ↓
创建任务文档
   ↓
开始开发
   ↓
执行验证
   ↓
更新任务状态
```

如果任务中断，下一次继续任务时，可以让 Agent 根据已有任务文档恢复现场。

---

## 这不是什么

这不是一个新的 Coding Agent。

也不是一个用来替代 Codex、Claude Code、Cursor 等工具的框架。

它目前更接近：

> **一份给 Coding Agent 使用的开发协作约定。**

它主要解决的是 Agent **如何完成一个开发任务**，而不是模型本身如何生成代码。

---

## 关于简单任务

并不是所有修改都需要创建任务文档。

例如：

* 修改错别字；
* 调整一个明确的配置；
* 修改局部样式；
* 非常明确的小范围代码修改。

这类任务可以直接完成。

只有当任务存在多个步骤、多个模块、依赖关系、需求不确定性，或者中断后难以恢复时，才需要进入完整工作流。

---

## 目前还在迭代

这套规则来自我实际使用 Coding Agent 开发过程中的不断调整。

它不是一套已经完成的“标准答案”。

实际使用过程中，我也会不断发现一些规则：

* 太重；
* 没有必要；
* 会产生额外干扰；
* 在真实项目中并不好用。

这些规则会继续调整甚至删除。

相比增加更多规则，我更希望最终留下的是：

> **真正能让 Agent 更稳定完成开发任务的规则。**

如果你在实际项目中使用后发现问题，欢迎提交 Issue 或 PR。
